## 給教師：開啟網站

### 最容易：單檔版

取得 `science-literacy-standalone.html` 後，用 Edge 或 Chrome 開啟。樣式、資料與互動均包在同一個檔案，不需安裝套件或連網。官方來源連結與外部 AI 工具需要網路。

### 完整專案版

1. 將 `science-literacy-v1.0-review.zip` 完整解壓縮。
2. 進入 `science-literacy` 資料夾，雙擊 `index.html`。
3. `styles.css`、`content.js`、`app.js`、`stage2.js`、`studio.js`、`learning.js` 必須與首頁放在一起。
4. 教師使用不需安裝 Node.js、Python 或 npm；測試工具只供維護者使用。

單檔版與完整專案是相同功能的兩種封裝。由於網址／檔案路徑不同，本機草稿不會互通。

目前檔案只在雲端執行環境 `/workspace/output`，這不是您的 Windows 資料夾。此執行環境未提供可用的檔案附件上傳工具，指定 /codex 輸出目錄也不可寫入。因此不能宣稱使用者已取得檔案。若對話中未出現實際可下載附件，請勿嘗試在自己電腦尋找 /workspace 路徑；仍需另行完成附件交付，或在明確授權後使用遠端託管方式。

## Windows 11 本機操作與驗收

以下是供使用者實做的步驟，本次沒有 Windows 11 機器，未將此說明當成已通過的實測。

1. 在「下載」找到取得的 ZIP，按右鍵 →「解壓縮全部」。不要直接在壓縮檔中開首頁。
2. 開啟解壓後的 `science-literacy/index.html`；若顯示文字而非網頁，按右鍵 →「開啟檔案」→ Microsoft Edge。
3. 由上方導覽進入 M01～M08。視窗縮窄時導覽會換行，寬表格可左右捲動。
4. 點兩組試題比較、六步驟與四階段示範；蒸發原題 B、改寫題 A、新題 C。確認正誤回饋及重新作答可用。
5. 到 M05 勾選部分項目、填備註，匯出並複製至「記事本」。重設後檢查欄位清空。
6. 到 M06，預設藍圖為 3 題×5 分＋1 題×10 分，應顯示 **4 題、25 分**。將第一列改為 7 題×4 分，應變為 **8 題、38 分**。
7. 改年級、學期、版本、單元、能力與命題模式，確認提示詞即時變化。列內能力必須也勾選於上方評量能力；分析／改題／審題須填原題。
8. 複製提示詞貼至記事本，或按「下載 TXT」查看瀏覽器下載清單。TXT 為 UTF-8 含 BOM，方便記事本顯示繁體中文。若無法自動複製，點備援文字框，按 Ctrl+C；手機長按選取後複製。
9. 按「儲存本機草稿」，更改單元後按「讀取本機草稿」，確認復原。重新開啟相同網址再手動讀取，確認能跨頁留存。
10. 按「清除已存草稿」，畫面應保留，之後讀取應顯示沒有草稿。此功能只刪本站專用鍵，不清其他網站資料。
11. 到 M08 切換 90 分鐘共備／45 分鐘自學，勾選五個活動、作答自我檢核、寫反思並匯出文字。這是自我紀錄，不是研習時數認證。
12. 用 Tab／Shift+Tab 與 Enter 操作，檢查焦點；以 Ctrl++ 放大到 200%。再用手機、平板檢查文字、按鈕、表格與橫向溢位，並記錄結果。

### 選用：本機 HTTP 預覽

若 Windows 已安裝 Python，可在解壓後的專案資料夾地址列輸入 `powershell`，執行：

```powershell
py -m http.server 8000 --bind 127.0.0.1
```

開啟 `http://localhost:8000`。完成後在 PowerShell 按 Ctrl+C 關閉。若找不到 `py`，可改 `python`；未安裝 Python 則使用雙擊方式即可。HTTP 方式通常比 file:// 有更一致的 localStorage 行為。本次沒有實際啟動 HTTP 服務。

## 工作室規則與限制

- 每列的「題數」是計分小題數；題組共同情境不另計分。每題配分乘題數為小計。
- 藍圖可留 1～20 列，題數 1～50、每題配分 1～100，均限整數。單元、已教內容、各列目標與內容為必填。
- 有效設定即時更新預覽；無效設定會清除預覽並停用複製與下載。這可避免匯出舊提示詞。
- 分析模式不出新題；改寫依原題保留核心概念；生成模式依藍圖出新任務；審題模式檢核原題。網站只產生提示詞，必須自行貼入外部 AI。
- 教材版本只是條件標籤，本站沒有出版社內容庫；課綱欄留白時會要求 AI 不得杜撰代碼。
- 草稿只在有效設定下手動儲存一份，保存工作室全部設定與原題。未自動儲存，也未自動載入；儲存按鈕會覆寫同網址先前草稿。
- 使用 localStorage 專用鍵 `science-literacy.studio.v1`，格式版本為 1。草稿損壞、不相容或無效時拒絕套用，保留畫面及已存內容供處理。清除只刪此鍵。
- 草稿依瀏覽器與網址來源分開；file://、HTTP、GitHub Pages 及單檔路徑可能各自不同。清瀏覽器資料會刪草稿，無痕模式關閉後可能遺失。
- 儲存權限、配額、下載及剪貼簿由瀏覽器控制。失敗會提示；請先複製或下載 TXT 備份。TXT 是提示詞，不是可匯入的草稿檔。
- M05 紀錄與 M08 進度僅保留當頁，重新整理清除，不含在工作室草稿。請先匯出文字留存。
- 不填學生個資。外部 AI 回覆須教師查核科學正確、適齡、課綱及公平性。

## GitHub Pages 部署教學

以下為免建置靜態網站的部署操作指引。本次未連線建立儲存庫、推送或發布，也未在 GitHub Pages 實測；執行這些步驟會將檔案交給 GitHub，公開 Pages 可能讓他人存取，請自行決定是否部署。

1. 登入 GitHub，建立新儲存庫；如使用一般公開 GitHub Pages，請確認您願意公開網站原始檔。不要加入學生資料、密鑰或私人草稿。
2. 解壓本專案，將 `science-literacy` 資料夾**裡面的檔案**上傳到儲存庫根目錄，讓根目錄直接看見 `index.html`。若整個資料夾再包一層，Pages 根路徑就找不到首頁。
3. 至少上傳 `index.html`、`styles.css`、`content.js`、`app.js`、`stage2.js`、`studio.js`、`learning.js`；建議一起保留 JSON、README 及進度報告。不要上傳 node_modules 或本機瀏覽器資料。
4. 進入儲存庫 **Settings → Pages → Build and deployment**，選 **Deploy from a branch**。
5. 選擇 `main` 分支、`/(root)`，按 **Save**。如果帳號或儲存庫設定不支援此方式，依 GitHub 當前介面處理，不需更動網站程式。
6. 等候 GitHub 的 Pages 部署完成，再使用 Pages 設定頁顯示的實際網址。專案型網址通常包含儲存庫名稱；不要自行猜測已發布成功。
7. 開啟網站，依前述驗收清單測試 M01～M08、複製、TXT、儲存／重新整理／讀取及手機版。
8. 若 404，確認分支與資料夾選對、`index.html` 位於根目錄；若缺少互動，確認所有 JS 檔案已上傳、檔名大小寫一致。所有資源為相對路徑，無需改成網站根路徑。
9. 更新時上傳新檔並等待重新部署；若不再需要公開，至 Pages 設定停用。變更網址／來源可能讓舊草稿無法讀取，請先下載 TXT。

維護者若以 Git 操作，可使用一般 commit／push，但本專案不附自動發布工作流程，避免未授權推送就發布。

## 維護者測試與重新封裝

網站不需要 npm；以下只供維護者。

1. 安裝符合 jsdom 31 要求的 Node.js：22.22.2 以上的 22.x、24.15.0 以上的 24.x，或 26 以上。
2. 在專案資料夾執行：

```sh
npm install --no-audit --no-fund
npm run check
npm test
```

本次使用環境已有的 jsdom 31.0.0（放在 work/test-runtime）並以 NODE_PATH 指向該套件執行，沒有把測試套件打進網站。測試包括純資料驗證、DOM 互動、模擬 localStorage／Clipboard／下載 API；不等同實體瀏覽器。

若已安裝 Python，執行：

```sh
python tools/package.py
```

會在專案上一層產生 `science-literacy-v1.0-review.zip` 與 `science-literacy-standalone.html`。打包不需要外部套件、不部署，也不會加入 node_modules。若修改 JSON，務必同步更新 content.js，測試會核對一致性。
