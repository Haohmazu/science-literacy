# AI 自然科學素養導向命題設計平台 V2.0

第一階段驗收版｜2.0.0-stage1｜2026-11-11（臺北）

目前只授權第一階段：三層版面、跨模組任務卡、統一資料與本機儲存，以及原功能相容性。第二階段尚未開始。完整 V2.0 需求書尚未提供，本版依使用者列出的四項範圍實作，詳細設計假設見 DEVELOPMENT_STATUS.md。

## 開啟與驗收

- 線上驗收路徑預定為 `https://haohmazu.github.io/science-literacy/v2-stage1/`；以 DEPLOYMENT_STATUS.md 的實際結果為準，未確認前不宣稱已上線。
- 原 V1 正式首頁維持 `https://haohmazu.github.io/science-literacy/`，不以本版取代。
- 取得 `science-literacy-v2-stage1.zip` 後完整解壓，開啟 science-literacy-v2-stage1/index.html。
- 或直接開啟 `science-literacy-v2-stage1-standalone.html`；單檔版包含樣式、資料與七份腳本，免安裝、免網路。官方來源與外部 AI 需要網路。
- 若 file:// 的儲存或複製受限，仍可使用提示詞 TXT 及手動複製。可選擇以 `python -m http.server 8000 --bind 127.0.0.1` 本機預覽。

## 三層導覽

1. 主頁籤：平台首頁、命題學習、AI 命題協作、資源與研習。
2. 次頁籤：首頁或 M01～M08。使用左右方向鍵、Home／End 切換，Tab 進出頁籤列。
3. 展開區塊：點選「好試題三個關鍵」「命題藍圖」「官方來源」等標題，展開或收合內容。

原頂部導覽、教學路徑及研習活動連結仍可用，會自動切到對應主／次頁籤並展開目標區塊。網址 hash 可連至模組，上一頁／下一頁依瀏覽歷史切換。頁籤只改變顯示，切換不會重建或重設表單。

## 共用命題任務卡

任務卡在所有工作區共用，點「編輯任務與管理本機資料」展開：

- 任務名稱、共同評量目標。
- 年級、學期、版本、單元、共用原題。
- 年級、學期、版本、單元與原題和 M06 雙向同步，兩處編輯是同一份資料。
- 任務名稱與共同目標會加入工作室提示詞、審題與學習匯出脈絡；不覆蓋藍圖各列目標。
- M04 的原題、改寫題、新題仍是固定蒸發教學示範，不會變成即時 AI 產物，也不會因修改任務卡而被覆寫。

## 統一本機資料

### 儲存／讀取／清除

- 按任務卡「儲存全部任務資料」：保存一份目前任務。
- 按「讀取已存資料」：以已存資料取代目前畫面，請先保存需要保留的修改。
- 按「清除 V2 已存資料」：只刪 V2 已存草稿，目前畫面、V1 草稿與其他站點資料保留。
- 工作室原有三個儲存按鈕也會使用同一服務，不再寫另一份 V1 草稿。
- **沒有自動儲存或自動讀取。** 重新開頁請手動讀取；新的儲存會覆寫同一份有效 V2 草稿。

包含：任務卡、工作室與藍圖、比較主題及六步驟位置、M04 作答與示範頁、M05 勾選／備註／審查者、M08 路徑／進度／答案／反思，以及目前模組。匯出預覽、複製備援及展開區塊狀態不保存，會依資料重建或回預設。

草稿可保存未完成條件；工作室依舊在條件有效時才輸出提示詞，無效時清空預覽並停用匯出。

### 匯入 V1 草稿

1. 使用和舊網站相同的瀏覽器及網址來源。
2. 展開任務卡，按「匯入 V1 工作室草稿」。
3. 確認年級、單元、原題與藍圖正確，再按「儲存全部任務資料」。

匯入只更新工作室資料，不丟棄當前任務名稱、審題或研習紀錄；原 V1 草稿不刪、不改，V1 網站仍可使用。匯入不會自動儲存或覆寫 V2。

GitHub Pages 的 V1 與 /v2-stage1/ 路徑同屬 `https://haohmazu.github.io`，故可讀同來源舊鍵；不同瀏覽器、網域、HTTP／HTTPS 或 file:// 不保證互通。無痕模式或清瀏覽器資料可能遺失草稿，請勿輸入學生個資。

### 保護措施與限制

- V2 鍵 `science-literacy.workspace.v2`，schema 2；V1 鍵 `science-literacy.studio.v1` 只供明確匯入。
- 損壞、超長或版本不相容時拒絕讀取及覆寫，保留畫面與原草稿。確定不需保留時可明確清除 V2，再儲存目前任務。
- 權限／配額失敗會提示，不宣稱已保存。
- 其他分頁更新已存草稿只顯示提醒，不自動合併；需要時手動讀取。沒有跨裝置或雲端同步。
- 完整「任務」不是 AI 生成結果；本站仍無 API、登入或付費服務。

## 教師第一階段驗收清單

1. 每個主頁籤及次頁籤都點一次，確認同時顯示一個模組；展開／收合第三層內容。
2. 用方向鍵、Home／End、Tab 操作頁籤；從 M07 官方來源舊連結進入，確認自動切頁並展開。
3. 在任務卡改年級、單元、原題，到 M06 確認同步；再由工作室改單元，確認任務卡同步。
4. 作答蒸發三題，保留不同答案；M05 勾兩項並填備註；M08 勾活動並寫反思。
5. 儲存全部任務，修改幾個欄位，再讀取，確認所有模組一起還原。重新開相同網址後再手動讀取一次。
6. 若有 V1 草稿，測試明確匯入，再回 V1 網站確認舊草稿仍可讀；不要在測試前清除瀏覽器資料。
7. 驗證工作室預設 4 題 25 分，改第一列為 7 題×4 分後共 8 題38 分；測試四模式、複製、TXT。
8. 桌面／平板／手機、200% 放大及實際剪貼簿／儲存需實機補驗。本次僅 DOM 與 API 模擬，不預設通過。

完成後提出修改或明確驗收；未授權前不開始第二階段。

## 維護與統一資料來源

- `content.json` 是正式教學資料的唯一編輯來源。包含原資料，以及集中後的 comparisons、workshop、studioOptions。
- 修改後執行 `python tools/sync-content.py` 產生 `content.js`。網站使用此 JS 載入版本，讓雙擊開啟不受 JSON fetch 限制；不要分別手動編輯兩份資料。
- `data-store.js`：統一資料、驗證、版本與本機儲存。
- `workspace.js`：三層 UI、共用卡片、模組資料介面整合。
- `app.js`、`stage2.js`、`studio.js`、`learning.js`：原有功能及 snapshot／restore 介面。舊測試不載入 V2 時仍可獨立驗證舊功能。

維護測試需 Node.js 22.22.2+ 的 22.x、24.15.0+ 的 24.x 或 26+，以及 jsdom 31：

```sh
npm install --no-audit --no-fund
npm run check
npm test
python tools/package.py
node tests/standalone.cjs
```

封裝產生 V2 第一階段 ZIP 與單檔 HTML，排除 Git、node_modules、downloads，避免把舊 ZIP 再包入。獨立驗收路徑發布時，將來源放入 main 的 v2-stage1/，把兩個新封裝檔放入該目錄的 downloads/。正式根目錄的 V1 檔案與下載包不改動。既有 GitHub Pages main／root 設定繼續使用，不需新增服務或付費設定。

實際測試與限制以 TEST_REPORT.md 為準；Windows、手機、Pages HTTP 下載不等於瀏覽器完整互動驗證。
